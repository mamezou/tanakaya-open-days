# 田中屋 営業日管理・自動告知アプリ 実行計画

Kiro University Challengeの最終課題として作る。
締切は2026年10月6日15:59（日本時間）。
7つの必須レッスンとボーナス2つをすべて実演し、5,250クレジットを狙う。

## 1. 前提と制約

- リポジトリはGitHub組織 `mamelabo-co-jp` 配下に新規の公開リポジトリとして作る。名前は `tanakaya-open-days` とする。
- 既存リポジトリのコードは持ち込まない。`.kiro` は `mamezou/kiro_project_template` から複製し、本プロジェクト向けに調整する。
- 顧客名を含む既存リポジトリの設定は流用しない。
- 秘密情報（LINEのチャネルアクセストークン、AWSの認証情報）はリポジトリに含めない。
- 締切後は、審査完了（2026年10月19日23:59 PT）か受賞メールの受信まで、リポジトリにコミットしない。

## 2. アプリの目的

田中屋は日曜だけ営業で、臨時の休業と営業がある。
休業のたびにLINE用とInstagram用の告知文と画像を手作業で作っている。
営業日を1か所で登録すれば、公開ページとLINEの告知が自動で更新される状態にする。

## 3. 機能要件（Specの元になる内容）

### 3.1 営業日の判定

- 既定の営業日は、設定ファイル（3.2）で指定した営業曜日とする。曜日はコードに固定しない。田中屋の営業曜日は日曜だけ。
- 例外として「休業日」と「臨時営業日」を日付単位で設定ファイル（3.2）に登録できる。
- 休業日は既定の営業日を休みにする。臨時営業日は既定外の日を営業にする。
- 例外は日付と種別（休業日・臨時営業日）だけを持つ。メモ欄は設けない。
- 営業時間は設定ファイル（3.2）の値として持ち、コードに固定しない。
- 日付と時刻の判定はすべて日本時間（Asia/Tokyo）で行う。

### 3.2 設定ファイルとデプロイ

- 営業曜日、休業日と臨時営業日、営業時間、LINEの前日配信時刻（初期値18:00）は、1つの設定ファイル `data/settings.json` に書く。
- イベントなどの案内は「お知らせ」として、日付ごとに1行の文と任意のリンクを同じ設定ファイルに書ける（2026-10-24 に追加。例外とは別の項目で、例外のメモ欄ではない）。
- `data/settings.json` は `.gitignore` で除外し、リポジトリには見本の `data/settings.example.json` だけをコミットする。提出後のコミット禁止期間（1章）にも、休業日を更新できるようにするため。
- 設定の変更は、手元の `data/settings.json` を書き換えてデプロイすることで反映する。
- `data/settings.json` がない、または形式が正しくない場合、デプロイを失敗させる。

### 3.3 公開ページ

- お客様向けのページとして、S3とCloudFrontで配信する。URLはCloudFrontの既定ドメインを使う。
- 表示内容は、今日の営業可否、営業時間、今月と来月の営業カレンダーとする。お知らせがある日は、カレンダーに印を付け、文とリンクを表示する。
- 公式LINEの友だち追加リンク（https://lin.ee/OReUh6e）とInstagram（https://instagram.com/tanakaya_ramen）へのリンクを置く。
- デプロイのたびに、設定ファイルから公開用のデータを生成する。
- 日付が変わっても「今日の営業可否」が正しく表示されるようにする。

### 3.4 LINEの前日自動配信

- 毎日、設定された配信時刻にEventBridge Schedulerで起動する。
- 翌日が次のいずれかの場合に、LINE公式アカウントの友だち全員へ配信する。
  - 既定の営業日で、例外がない（通常営業の案内）
  - 既定の営業日だが休業日に登録されている（臨時休業の案内）
  - 臨時営業日に登録されている（臨時営業の案内）
- 翌日が既定の非営業日で例外もない場合は配信しない。
- 翌日にお知らせがある場合は、案内にその文とリンクを加える。
- 同じ対象日について、自動配信は最大1回とする。配信記録をDynamoDBに保存し、二重配信を防ぐ。
- 配信後に例外が変更された場合は、自動では再配信しない。訂正は、LINE公式アカウントの管理画面（LINE Official Account Manager）から手動で送る。
- 配信にはLINE Messaging APIを使う。チャネルアクセストークンはSSM Parameter StoreのSecureStringに置く。
- 通常営業の案内も送る。月の通数の上限は送る前に確かめない。上限などで送信APIが失敗した日は、再送せずに失敗を記録する。

### 3.5 範囲外

- 管理画面（Amazon Cognitoでの認証、カレンダーでの例外の登録、本アプリからの訂正配信を含む）
- Instagram用の素材生成（カレンダー画像、キャプション文面）
- Instagramへの自動投稿
- 独自ドメインでの公開ページ配信
- 予約受付、売上管理
- 祝日の扱い（祝日による営業・休業の判定）。祝日に営業や休業をするときは、例外として登録する

## 4. 技術構成

- 言語はTypeScript。公開ページは静的HTMLとJSONで作る。
- バックエンドはAWS Lambda、Amazon DynamoDB、Amazon EventBridge Scheduler。
- 配信基盤はAmazon S3とAmazon CloudFront。
- IaCはAWS SAM。アプリの実行リージョンは東京（ap-northeast-1）。
- テストは単体テストとプロパティベーステストの両方を持つ。

### 5.1 Steeringに書く内容

- `product.md`：田中屋の営業ルール（3.1）、用語、お客様向け表示に出してよい情報と出さない情報
- `tech.md`：4章の技術構成、日本時間での日付処理、秘密情報の置き場所
- `structure.md`：ディレクトリ構成
- `testing.md`：プロパティベーステストの方針（5.2）
- `line-messaging.md`：本番アカウントへの配信は明示の指示がある場合だけ行う、試験送信はテスト用アカウントだけに行う
- テンプレートの `coding-standards.md`、`git-conventions.md`、`production-safety.md`、`pre-commit-checks.md` は残して調整する。
- テンプレートのうち本プロジェクトに関係しない記述は削除する。

### 5.2 プロパティベーステストで検証する性質

- 休業日に登録した日は、どの登録内容でも営業と判定しない。
- 臨時営業日に登録した日は、どの登録内容でも休業と判定しない。
- 例外がない日は、設定した営業曜日だけが営業と判定される。
- 例外を登録してから削除すると、判定が登録前と一致する。
- 配信処理を同じ日に何回実行しても、同じ対象日への自動配信は1回以下になる。
- 配信対象日は常に実行日の翌日（日本時間）で、月末、年末、日付の境界でもずれない。
- 公開用データの各日の表示が、判定関数の結果と一致する。

### 5.3 Hooks

- `src/` 配下のTypeScriptファイルの保存時に、単体テストとプロパティベーステストを実行する。
- `.kiro/specs/` 配下のrequirementsの変更時に、designとtasksへの影響をエージェントに確認させる。
- テンプレートの `auto-test` と `auto-commit` は内容を確認し、本プロジェクトに合わせて調整するか削除する。
- 使えるイベントの種類はKiroの公式ドキュメントで確認してから設定する。

### 5.4 MCPとカスタムエージェント

- 開発用にLINE公式アカウントをもう1つ作り、Messaging APIを有効にする。友だちは田中さんだけにする。
- LINE Bot MCP Serverはテスト用アカウントのトークンで接続する。
- カスタムエージェントは次の構成にする。
  - `line-tester`：LINE Bot MCP Serverだけを使える。テスト用アカウントへの試験送信だけを行う。
  - `spec-checker`（テンプレートから調整）：実装がrequirementsを満たしているか確認する。
  - `security-auditor`（テンプレートから調整）：トークンの扱いと、公開ページに秘密情報が出ていないかを確認する。
  - `unit-tester`（テンプレートから調整）：単体テストとプロパティベーステストを追加する。
- LINE Bot MCP Serverを使えるのは `line-tester` だけに限定する。

### 5.5 自作Power（ボーナス2）

- `powers/line-announce/` に、LINE Bot MCP Serverの接続設定と、安全な配信手順のsteeringをまとめる。
- 安全な配信手順には、テスト用アカウントでの確認、本番配信前の文面確認、無料プランの月200通の上限の確認を含める。
- Powerのファイル構成はKiroの公式ドキュメントに従う。

## 6. 本番LINE公式アカウントの設定

- 本番の田中屋の公式アカウントでMessaging APIを有効にする。
- Messaging APIのチャネルは、公式アカウントを残したまま削除できない。有効にした後はWebhookを無効にして止める形になる。
- 本アプリは配信だけを行うため、Webhookは使わない。
- 本番アカウントへの配信確認は、10月5日のデプロイ後に1回だけ行う。
